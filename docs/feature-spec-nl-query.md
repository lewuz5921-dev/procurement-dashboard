# 功能规格：自然语言问数（对话式数据分析 Agent）

> 版本 v1.0 ｜ 状态：待开发 ｜ 所属产品：采购数字化数据看板
> 作者角色：产品经理（个人项目）

---

## 1. 问题陈述

采购经理要看数据，当前必须"迁就产品"而不是"产品迁就人"：

- 想回答一个简单问题（如"上月哪些供应商 OTD 低于 80%"），需要记住每个页面在哪、手动切换筛选器、逐个翻表格，才能拼出答案。
- 看板是"死的"——只能被动展示预设好的视图，无法响应用户临时冒出的具体问题。
- 数据价值的最后一公里没有被"问"出来：数据都在，但取数门槛高，导致大多数采购人员宁可凭经验，也不去用看板。

**代价**：看板使用率低、决策仍靠直觉、数据资产没有被充分转化为决策能力。这也是"AI + 大数据"结合的典型机会点——用 AI 降低取数门槛，用大数据提供真实答案。

## 2. 目标

**用户目标**
1. 用一句话问出答案，无需学习看板操作。
2. 答案是可信的、可追溯的，不是 AI 编的。
3. 问不出/不会答时，能得到明确提示，而不是错误答案。

**产品目标**
4. 展示"AI 理解意图 + 大数据计算答案"的落地能力（直接回应该岗位 JD）。
5. 面试现场 30 秒内可演示出结果。

## 3. 非目标（Non-Goals）

| 不做的事 | 原因 |
|---------|------|
| 不回答"异常归因 / 预测"类问题 | 归因是规则引擎的职责，预测在模拟数据上无说服力 |
| 不做通用闲聊（"今天天气"） | 窄域 Agent，越界明确拒绝，防止套壳感 |
| 不做 RAG 知识问答 | 无非结构化知识库，硬套反而假 |
| 不做多轮复杂对话 | v1 单轮，降低实现复杂度 |
| 不做数据写入 / 修改 | 只读查询，避免副作用 |
| 不替代「智能洞察」模块 | 洞察=系统主动推异常，问答=用户主动查数据，两者互补不重叠 |

## 4. 用户故事

按优先级排序：

1. **作为采购经理**，我想问"上月 OTD 低于 80% 的供应商有哪些"，以便快速定位交付问题供应商，而不是翻履约页。
2. **作为采购经理**，我想问"电子元器件品类谁占采购额最大、占比多少"，以便评估单一供应商依赖风险。
3. **作为供应链负责人**，我想问"哪个品类价格涨幅最快"，以便判断成本压力来源。
4. **作为用户**，当我的问题超出数据范围时，我希望能得到明确提示，而不是一个看似合理实则错误的答案。

**边界用例**
- 问法含糊（"最近怎么样"）→ 提示无法理解，并展示支持的问题类型示例。
- 指标不支持（"哪家供应商的老板是谁"）→ 明确回复"这个问题超出我能查询的数据范围"。
- 空结果（没有供应商 OTD < 80%）→ 明确回复"当前时间范围内没有符合条件的记录"。

## 5. 需求

### P0（必须，MVP）

| # | 需求 | 验收标准 |
|---|------|---------|
| R1 | 意图解析：LLM 把自然语言解析为结构化查询参数（见 §6 输出契约），用 Function Calling 强制 schema | 输入自然语言，返回合法的 JSON 查询参数；非法参数被拒绝 |
| R2 | 查询执行：确定性函数执行查询，返回真实数据 | 答案数值与看板其他页面一致，可交叉核对 |
| R3 | 答案渲染：模板把查询结果拼成自然语言回复 | 输出包含真实数字 + 一句可读结论 |
| R4 | 支持 ≥5 类核心问题（见 §7 问题类型清单） | 每类问题的示例问法均能正确回答 |
| R5 | 防幻觉：LLM 不生成答案正文，越界问题明确拒绝 | 对"今天天气"类问题，回复拒绝话术而非瞎答 |
| R6 | 模块入口：侧边栏新增「智能问答」页 | 导航可见、页面可访问 |

## 6. 输出契约（JSON Schema）

LLM 只输出以下结构化查询参数（Function Calling 强制），**不输出任何答案正文**：

```json
{
  "target": "supplier",        // supplier | category | order
  "metric": "otd",             // otd | spend | quality | tco | savings | price_trend | concentration
  "operator": "<",             // < | > | = | top_n
  "value": 80,                 // 阈值（top_n 时为 N）
  "time": "last_month",        // last_month | last_3_months | last_12_months | all
  "category": null             // 可选：限定品类
}
```

**契约原则**：
- `target` / `metric` / `operator` 必须在白名单枚举内，否则视为无法解析。
- 答案正文由「查询函数返回值 + 模板句式」拼接生成，LLM 全程不接触答案内容。

## 7. 支持的问题类型清单（v1）

| 类别 | 示例问法 | 对应指标 |
|------|---------|---------|
| 供应商履约 | 上月 OTD 低于 80% 的供应商有哪些 | otd |
| 供应商排名 | 采购额最大的 5 家供应商 | spend (top_n) |
| 品类分析 | 电子元器件占采购额多少 / 谁最大 | concentration |
| 成本分析 | 哪个供应商 TCO 最高 | tco |
| 价格趋势 | 哪个品类价格涨得最快 | price_trend |
| 质量 | 验收合格率最低的供应商 | quality |

## 8. 防幻觉架构（四层防御）

| 防线 | 做法 | 挡住什么 |
|------|------|---------|
| ① 架构隔离 | LLM 只做意图解析，答案来自确定性函数，LLM 接触不到数据 | 源头杜绝编造 |
| ② 强制结构化 | Function Calling 必须返回 schema 参数，格式不符即拒绝执行 | 自由发挥 / 加戏 |
| ③ 白名单限域 | 只允许查询预设指标，越界明确回复"无法回答" | 答非所问 |
| ④ 可追溯 | 答案附数据依据（时间范围、订单数） | 无法核对的答案 |

## 9. 成功指标

**Demo 阶段验证目标**（面试演示）：
- 5 类核心问题的示例问法 100% 正确回答。
- 越界问题 100% 正确拒绝（不幻觉）。
- 单次回答耗时 < 3 秒（含 LLM 调用）。

**产品化假设**（若真实上线，供后续验证）：
- 30 天内 50% 目标用户试用过该功能（adoption）。
- 相比手动翻看板，"问出一个答案"的时间降低 80%。
- 越界/无法解析的问题占比 < 15%。
